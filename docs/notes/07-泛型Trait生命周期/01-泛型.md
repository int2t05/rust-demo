# Generics(泛型)

一句话:泛型把类型变成参数 `<T>`,一份代码适配多种类型,编译时单态化成具体版本,运行时零开销。

## 它解决什么问题

为 i32 和 char 各写一个「找最大值」,逻辑一模一样,只差类型——每加一种类型就复制一份,没人维护得动。泛型把重复的类型维度抽成占位符:逻辑只写一次,具体类型由调用处决定。

约束(trait bound)是泛型的另一半:`item > max` 要求 T 会比较大小,所以 `<T: PartialOrd>` 不是装饰,而是让编译器验证「这份代码对 T 成立」。

## 核心规则

泛型代码不直接运行,编译器为每个用到的具体类型生成专用副本(单态化):

```mermaid
flowchart LR
  A["泛型源码:一份逻辑,类型是参数"] --> B["编译期单态化"]
  B --> C["每种用到的具体类型各生成一份专用副本"]
  C --> D["运行时零开销,如同手写各类型版本"]
  B --> E["代价:二进制随用到的类型增多而变大"]
```

- 四处可写泛型:函数、结构体、枚举、`impl`;标准库的 `Option<T>`/`Result<T, E>` 本身就是泛型枚举。
- `impl<T> Point<T>` 为所有 T 实现方法;`impl Point<f64>` 只给具体类型加方法,因此能用 `f64` 独有的运算。
- 类型参数可以有多个(`Point<T, U>`),方法还能自带新参数(`mix<V, W>`),输入输出的类型可自由重组。

## 示例

摘自 `20-generics/src/main.rs`:

```rust
/// 泛型函数：找出切片中最大的元素
/// T: PartialOrd 约束 T 必须支持比较
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut max = &list[0];
    for item in &list[1..] {
        if item > max {
            max = item;
        }
    }
    max
}

/// 泛型结构体：坐标点，x 和 y 同类型
#[derive(Debug)]
struct Point<T> {
    x: T,
    y: T,
}

/// 多类型参数：x 和 y 可以是不同类型
#[derive(Debug)]
struct MixedPoint<T, U> {
    x: T,
    y: U,
}

// 泛型方法实现
impl<T> Point<T> {
    fn get_x(&self) -> &T {
        &self.x
    }
}

// 为特定类型添加额外方法
impl Point<f64> {
    fn distance_from_origin(&self) -> f64 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}

// MixedPoint 的泛型方法：混合另一个 Point 的坐标
impl<T, U> MixedPoint<T, U> {
    /// 用当前 x 和另一个点的 y 组合成新点
    fn mix<V, W>(self, other: MixedPoint<V, W>) -> MixedPoint<T, W> {
        MixedPoint { x: self.x, y: other.y }
    }
}
```

调用处(main 节选):

```rust
let p_int = Point { x: 5, y: 10 };
let mixed = MixedPoint { x: 5, y: 3.14 }; // T = i32, U = f64

let some_int: Option<i32> = Some(42);
let ok: Result<i32, &str> = Ok(100);
```

## 源码解读

crate:`20-generics/src/main.rs`,`cargo run -p generics_demo` 可运行。

| 小节 | 演示什么 | 关键行 |
|---|---|---|
| 泛型函数 | 一份代码适配所有可比较类型,`PartialOrd` 是能编译的前提 | `fn largest<T: PartialOrd>(list: &[T]) -> &T` |
| 泛型结构体 | `Point<T>` 字段同类型,`MixedPoint<T, U>` 允许异类型 | `let mixed = MixedPoint { x: 5, y: 3.14 }` |
| 泛型方法 | `impl<T>` 全类型可用,`impl Point<f64>` 仅具体类型可用 | `p_float.distance_from_origin()` |
| mix 组合 | 方法自带新泛型参数 V、W,重组两点的坐标类型 | `let m3 = m1.mix(m2)` |
| 泛型枚举 | 标准库 `Option<T>`/`Result<T, E>` 即泛型枚举 | `let some_int: Option<i32> = Some(42)` |
| 单态化 | 编译时生成具体类型副本,运行时零开销 | 末尾 `[单态化]` 输出 |

## 避坑

- `Point<T>` 的 x、y 必须同类型;要混类型就用 `MixedPoint<T, U>`,编译器不会替你放宽。
- bound 不是可省的仪式:去掉 `PartialOrd`,`item > max` 直接编译失败;bound 是这份泛型代码成立的最小假设。
- 单态化不是免费午餐:运行时零开销,代价是每种类型一份代码,二进制变大。
