# Concurrency(并发)

一句话:`thread::spawn` 开线程,`move` 转移所有权、通道传数据、`Mutex` 锁共享,`Send`/`Sync` 在编译期守住线程安全。

## 它解决什么问题

单线程干不完的活交给多线程同时干,但两个线程同时读写同一块内存就是数据竞争,结果随调度时序变化。其他语言靠程序员自觉加锁,Rust 把检查搬进编译器:进线程的数据必须 `Send`,共享引用必须 `Sync`,不安全直接编译失败。标准库给三种协作方式:线程各自算完用 join 收结果;数据单向流动用 mpsc 通道;多线程改同一份数据用 `Arc` 包 `Mutex`。

## 核心规则

数据跨线程只有三条路,按「数据怎么用」选:

- 闭包进线程几乎都要 `move`:闭包默认借用栈上数据,而线程可能活得比数据久,编译器直接拒绝。
- `T: Send` = 所有权可跨线程转移;`T: Sync` = `&T` 可跨线程共享,且 `T: Sync` 当且仅当 `&T: Send`;二者由成员自动推导——`Rc`/`RefCell` 都不是,分别换成 `Arc`/`Mutex`。
- 通道是所有权管道:`send` 把值交给接收端;`for received in rx` 要等所有发送端(含 clone 出来的)drop 才结束。
- `Arc` 管「共享所有权」,`Mutex` 管「独占访问权」:单线程只需 `Mutex<T>`,跨线程共享才加 `Arc`;`lock()` 返回的 `MutexGuard` 一 drop 就解锁。

## 示例

摘自 `27-concurrency/src/main.rs`:

```rust
use std::sync::mpsc;
use std::sync::{Arc, Mutex};
use std::thread;
use std::time::Duration;

// ===== 1. spawn 与 join =====
// spawn 返回 JoinHandle,调用 join 阻塞等待线程结束
let handle = thread::spawn(|| {
    // ...打印 1..=3,每次 sleep 10ms...
    42
});
// join 等待并取回返回值
let result = handle.join().unwrap();

// ===== 2. move 闭包 =====
// 不加 move,闭包借用 data,线程可能在 data 释放后访问 -> 编译错误
// 加 move,把 data 所有权转移到线程
let data = vec![1, 2, 3];
let handle = thread::spawn(move || {
    println!("  线程内 data: {:?}", data);
    data.len()
});
let len = handle.join().unwrap();

// ===== 3. mpsc 通道 =====
// mpsc: multiple producer, single consumer
let (tx, rx) = mpsc::channel();
let handle = thread::spawn(move || {
    let msgs = vec!["hello", "from", "child"];
    for m in msgs {
        tx.send(m).unwrap();
        thread::sleep(Duration::from_millis(10));
    }
});
// 主线程接收:rx 是迭代器,每次 yield 一个收到的值
for received in rx {
    println!("  收到: {}", received);
}

// ...第 4 节多生产者,第 5 节单线程 Mutex,第 7 节 Send/Sync 断言省略...

// ===== 6. Arc<Mutex<T>> 共享可变 =====
// Arc 多线程共享所有权,Mutex 提供可变性
let counter = Arc::new(Mutex::new(0));
let mut handles = vec![];
for _ in 0..10 {
    let counter = Arc::clone(&counter);
    let handle = thread::spawn(move || {
        let mut num = counter.lock().unwrap();
        *num += 1;
    });
    handles.push(handle);
}
for h in handles {
    h.join().unwrap();
}
println!("  10 线程各 +1 后计数器 = {}", *counter.lock().unwrap());

// ===== 8. 简单线程池概念 =====
// 用通道 + 固定数量的 worker 模拟线程池
let (job_tx, job_rx) = mpsc::channel::<Box<dyn FnOnce() + Send + 'static>>();
let job_rx = Arc::new(Mutex::new(job_rx));
let mut workers = vec![];
for id in 0..4 {
    let job_rx = Arc::clone(&job_rx);
    let handle = thread::spawn(move || loop {
        // 加锁取出一个任务;通道关闭时退出
        let job = {
            let guard = job_rx.lock().unwrap();
            guard.recv()
        };
        match job {
            Ok(j) => { println!("  worker {} 执行任务", id); j(); }
            Err(_) => { println!("  worker {} 退出", id); break; }
        }
    });
    workers.push(handle);
}
drop(job_tx); // 关闭发送端,worker 收到 Err 后退出
```

## 源码解读

crate:`27-concurrency/src/main.rs`,`cargo run -p concurrency_demo` 可运行。

| 小节 | 演示什么 | 关键行 |
|---|---|---|
| 1. spawn 与 join | 子线程与主线程并行,join 阻塞等待并取回返回值 42 | `handle.join().unwrap()` |
| 2. move 闭包 | 借用无法证明比线程长寿,move 把 data 所有权搬进线程 | `thread::spawn(move \|\| ...)` |
| 3. mpsc 通道 | send 转移所有权,rx 作迭代器收完自动结束 | `mpsc::channel()`、`for received in rx` |
| 4. 多生产者 | clone 出多个发送端,两个线程各自 send | `tx.clone()`、`rx.iter().collect()` |
| 5. Mutex | 单线程互斥访问,guard 出作用域自动解锁 | `let mut num = m.lock().unwrap()` |
| 6. Arc\<Mutex\<T\>\> | 十个线程共享计数器各 +1,结果精确为 10 | `Arc::clone(&counter)` |
| 7. Send / Sync | 泛型约束断言 Arc 是 Send+Sync;Rc 跨线程被拒(注释) | `fn assert_send_sync<T: Send + Sync>` |
| 8. 简单线程池 | 通道发任务,`Arc<Mutex<Receiver>>` 让 4 个 worker 抢活,关发送端即收尾 | `Arc::new(Mutex::new(job_rx))`、`drop(job_tx)` |
| 9. 总结 | 打印线程/通道/共享/安全四条主线回顾 | 无新代码 |

## 避坑

- 忘了 join:主线程结束整个进程退出,没 join 的子线程被硬砍——handle 要留着统一 join。
- `MutexGuard` 活太久:guard 一 drop 才解锁,把 `lock()` 放进小作用域 `{}`,别让整个函数都持锁。
